# 开发报告：商城退款与兑换（GS-2026-1199）

> 这是一份**故意写错接口规范**的报告，用来演示"报告阶段就拦住"：
> 接口ID 重复、鉴权留空、写接口没幂等键、方法写成 FETCH、路径大写加下划线、
> 回调没写验签。规范校验不通过时，流水线**不会拆包、不会下发开发**。

## 背景与目标

商城需要支持退款与道具兑换，退款要走支付平台回调，兑换要走积分扣减。

## 范围

- 商城服新增退款、兑换、商品列表接口；
- 支付平台回调改为新路径；
- 客户端展示退款状态。

## 玩法与业务规则

1. 退款成功后原路退回，兑换扣积分后发道具。
2. 回调必须验签，重复回调不得重复退款。

## 数据与存储

- 新表 `refund_order`、`exchange_record`。

## 验收标准

- 退款成功后原路退回且不重复退款
- 兑换扣积分与发道具在同一事务
- 回调验签失败必须拒绝
- 商品列表分页正确

## 模块拆分

- 商城退款：`server/shop.py`
- 兑换与积分：`server/points.py`
- 支付回调：`server/pay_callback.py`

## 排期与风险

- 服务端 3 人日；风险：支付回调乱序导致重复退款。
