# 游戏服务端设计文档（示例）

## 登录与鉴权

登录接口本身不鉴权；其余玩家接口必须带鉴权标记。封禁接口只允许管理员调用，
实现时必须 `auth=True`，否则属于越权。

登出接口（`POST /v1/player/logout`）同样需要鉴权，且必须实现，否则客户端会一直持票。

## 匹配加入

匹配加入使用事务，避免并发下同一玩家进两个房间。
客户端必须传 `request_id` 作为幂等键，重复请求直接返回第一次的结果，不重复进房。

## 商城扣费

商城扣费走事务：扣款与发货必须在同一事务里，任何一步失败都整体回滚。
同样要求 `request_id` 幂等，防止重放导致重复扣费。

## 掉落与经济

掉落概率合计不得超过 1（同一掉落组内）；道具 ID 必须存在于道具表。
每日产出上限（faucet_daily_cap）必须配置，禁止为 0；每日通胀超过 0.5% 需要预警。
